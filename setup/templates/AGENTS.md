## Working standard

- Before asking for help, use every relevant source and safe check within the task's scope.
- For material decisions, give the problem, viable options with tradeoffs, your recommendation, and your assumptions. Keep the comparison open to further options and evidence.
- Identify the source that establishes the applicable requirement or behavior. Inspect existing tools and platform features against that requirement, and reuse the mechanism that fits.

## Documentation

- Code implements behavior, and tests check it against requirements. Documentation supplies intent, constraints, contracts, durable decisions, operating guidance, and navigation that readers need alongside the implementation.
- Comments explain information beyond the code itself: a constraint, an alternative considered, domain meaning, compatibility history, or safety rationale. Keep implementation detail in the code and change history in the commit.
